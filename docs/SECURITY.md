# Security: token handling

## Token scope

A fine-grained PAT limited to selected repositories, with **Actions: read**, **Contents: read** (needed for the branch list, V2) and **Metadata: read** (D7). The app never asks for write permissions. The user guide is [user/TOKEN.md](user/TOKEN.md).

## Storage

- Key: an AES-256 key in the Android Keystore (`KeyGenParameterSpec`, alias `cidget_token_v1`, purposes ENCRYPT|DECRYPT, `BLOCK_MODE_GCM`, `ENCRYPTION_PADDING_NONE`, `setRandomizedEncryptionRequired(true)`, no user authentication). StrongBox is not requested (slow, not needed).
- Cipher: `AES/GCM/NoPadding`, IV generated by the cipher (12 bytes), 128-bit tag. The file layout of `files/token.bin` is `version(1 byte) | ivLen(1) | iv | ciphertext`. Write atomically (temp file + rename).
- **Do not** use `EncryptedSharedPreferences` or `androidx.security:security-crypto` (deprecated).
- Decrypt on demand for each refresh, keep the plaintext only in a local variable, and never in a long-lived object, settings or Compose state.
- If decryption fails (`KeyPermanentlyInvalidatedException`, `AEADBadTagException`, missing key or file): delete the file and the key, treat the state as *no token*, and show `! no token`.

## Rules

1. The token is never logged, put in exceptions, crash messages, the HTTP cache key, notifications, widgets or share text. OkHttp logging, in debug builds only, uses `HttpLoggingInterceptor.redactHeader("Authorization")`. Release builds have no HTTP logging.
2. The token is never in source code, resources, `BuildConfig` or tests. Tests use fake tokens such as `github_pat_TEST`.
3. The token input field uses `KeyboardType.Password`, no autocorrect, and is masked with a show/hide toggle. The settings screen shows only the last 4 characters of a saved token.
4. Replace token: validate it first with `GET /user/repos?per_page=1`, then save. Delete token: remove the file and key, evict the HTTP cache and all snapshots, update widgets.
5. On `401`, set the token state to `INVALID`; periodic work stops calling the API until the token is replaced.
6. `android:allowBackup="false"`; the cache, snapshots and token file stay in app-private storage.
7. Network: HTTPS only (`usesCleartextTraffic="false"`); no certificate pinning (GitHub rotates certificates).
8. Release builds use R8 minification.
